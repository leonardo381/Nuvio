# Page Patterns

## Purpose

This document gives Website Factory agents practical page patterns. Use it during Stage 2 sitemap planning and Stage 3 page blueprinting.

Patterns are not mandatory templates. They help avoid missing critical sections and avoid overweight pages.

## Home Page Pattern

| Area | Guidance |
| --- | --- |
| Purpose | Explain the business/site offer quickly, build trust, and move visitors to the primary CTA. |
| Minimum sections | Hero; problem/value proposition; what the business gets; services/modules/highlights; how it works; CTA; footer. |
| Optional sections | Proof/demo/preview; testimonials/logos; FAQ; pricing teaser; featured work. |
| CTA role | One primary CTA repeated at natural decision points; one secondary CTA only if useful. |
| Recommended block types | Hero with CTA; problem cards; feature/service cards; steps; product/mockup preview; proof strip; final CTA. |
| Visual rhythm | Strong hero, compact problem, medium detail, visual proof, simple final CTA. |
| Common mistakes | Too many feature cards; vague SaaS copy; burying CTA; opening with internal product structure. |
| Keep simple when | The business has limited content, no proof assets, or the goal is a quick first launch. |

Minimum Home sections:

- Hero
- Problem/value proposition
- What business gets
- Services/modules/highlights
- How it works
- Proof/demo/preview if available
- CTA
- FAQ optional
- Footer

## Services Page Pattern

| Area | Guidance |
| --- | --- |
| Purpose | Explain what is delivered, who it helps, and how service areas connect to business outcomes. |
| Minimum sections | Hero/positioning; service overview; service categories/cards; process/steps; benefits/outcomes; FAQ; CTA. |
| Optional sections | Comparison; deliverables; integrations; examples; operations/support model. |
| CTA role | Convert service interest into review/contact request or pricing/process page. |
| Recommended block types | Service cards; split feature rows; process steps; comparison table; FAQ; CTA band. |
| Visual rhythm | Start broad, then group services, then process, then reassurance, then CTA. |
| Common mistakes | Listing features without outcomes; overpromising; duplicating pricing page; making every card equal priority. |
| Keep simple when | Services are few, pricing is custom, or the audience needs clarity more than exhaustive detail. |

Minimum Services sections:

- Hero/positioning
- Service overview
- Service categories/cards
- Process/steps
- Benefits/outcomes
- FAQ
- CTA

## Contact Page Pattern

| Area | Guidance |
| --- | --- |
| Purpose | Make the next step low-friction and set expectations for response and fit. |
| Minimum sections | Hero; contact options; WhatsApp/contact form; expectations/response time; CTA. |
| Optional sections | Location/service area; booking entry; risk reducers; what to include in the message. |
| CTA role | Encourage the visitor to submit a useful inquiry without pressure. |
| Recommended block types | Contact hero; form card; contact option cards; steps; reassurance strip; final CTA. |
| Visual rhythm | Short hero, form visible early, supporting reassurance nearby, no distraction-heavy sections. |
| Common mistakes | Hiding the form; asking too many fields; making WhatsApp compete with form without purpose; promising instant results. |
| Keep simple when | The business only needs one form and one direct contact path. |

Minimum Contact sections:

- Hero
- Contact options
- WhatsApp/contact form
- Location/service area if relevant
- Booking entry if relevant
- Expectations/response time
- CTA
