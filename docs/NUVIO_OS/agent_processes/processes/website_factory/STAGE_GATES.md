# Website Factory Stage Gates

## Purpose

This file is the compact gate checklist for Website Factory stages. Use it before starting a stage and before moving to the next stage.

## Global Gate Rules

- Do not start a stage without its required inputs or an explicit `Unknown / needs confirmation` note.
- Do not perform work from another stage.
- Do not modify source blocks.
- Do not store secrets, credentials, tokens, private client data, or unnecessary PII in artifacts.
- Do not proceed past a P0.

## Gate Checklist

| Stage | Entry gate | Allowed work | Forbidden work | Required output | Exit gate | Cannot proceed if |
| --- | --- | --- | --- | --- | --- | --- |
| 0 - Intake | User request or sales notes<br>Business name and type<br>Known goals and constraints | Ask only concrete missing intake questions<br>Record unknowns as `Unknown / needs confirmation`<br>Identify constraints, audiences, CTAs, integrations, and available content | Designing layouts<br>Selecting source blocks<br>Writing final copy | `SITE_BRIEF.md` | `SITE_BRIEF.md` exists<br>Goals, audience, pages, CTA, brand inputs, integrations, unknowns, and constraints are captured | Business identity is unknown<br>Primary CTA is unknown and cannot be inferred safely |
| 1 - Audit / strategic analysis | `SITE_BRIEF.md`<br>Existing site or profile links when available<br>Current content/assets | Assess current positioning<br>Identify conversion, content, SEO basics, and trust gaps<br>Identify opportunities and risks | Locking the sitemap<br>Selecting blocks<br>Writing final copy | `WEBSITE_AUDIT.md` | Audit contains strengths, problems, content gaps, conversion issues, SEO basics, technical risks, opportunities, and recommended direction<br>No sitemap is locked | No meaningful business or current-state information exists<br>The audit requires private credentials |
| 2 - Sitemap / page plan | `SITE_BRIEF.md`<br>`WEBSITE_AUDIT.md`<br>Confirmed business goals | Propose pages and routes<br>Assign page purpose and primary CTA<br>Mark priority and dependencies | Selecting blocks<br>Copying blocks<br>Writing final section copy | `SITEMAP.md` | Every planned page has route, purpose, CTA, priority, dependencies, and status<br>Deferred pages are explicitly marked | Primary launch pages cannot be agreed<br>A required page depends on missing legal/commercial content |
| 3 - Page blueprint | `SITEMAP.md`<br>`SITE_BRIEF.md`<br>`WEBSITE_AUDIT.md` | Define page sections<br>Define section goals, content needs, CTA role, and visual role<br>Suggest block type categories without choosing exact source files | Copying source blocks<br>Selecting exact source block files<br>Writing final copy | `PAGE_BLUEPRINTS.md` | Each page has ordered sections with goal, content needed, CTA role, visual role, suggested block type, and notes | A page purpose is unclear<br>Required content is unavailable and affects structure |
| 4 - Block selection | `PAGE_BLUEPRINTS.md`<br>Approved source block library path<br>Known target stack constraints | Inspect source block files read-only<br>Select exact source blocks<br>Record source path, target page/section, rationale, fit notes, risks, and dependencies | Editing source blocks<br>Copying blocks into the target repo<br>Adapting copy or brand | `BLOCK_SELECTION.md` | Every selected block has source path, target page/section, reason, fit notes, risks, and dependencies<br>Source files remain untouched | No approved block matches a critical section<br>A block requires dependencies not approved for the target site |
| 5 - Raw block import | `BLOCK_SELECTION.md`<br>Target repo path<br>Approved source blocks | Copy selected blocks<br>Copy required unchanged assets<br>Fix import paths, file paths, dependency paths | Changing copy/text<br>Changing visual hierarchy<br>Redesigning layout | `BLOCK_IMPORT_LOG.md` | Copied blocks exist in target repo<br>Only allowed minimal fixes were made | A block cannot compile without redesign<br>An unapproved dependency is required |
| 6 - Page assembly | Imported blocks<br>`PAGE_BLUEPRINTS.md`<br>`BLOCK_IMPORT_LOG.md` | Place imported blocks into target pages/routes<br>Wire static anchors and internal links required by the blueprint<br>Perform minimal composition adjustments required to make blocks coexist | Final copywriting<br>Brand redesign<br>CMS integration | `PAGE_BLUEPRINTS.md / BLOCK_IMPORT_LOG.md updates` | Pages exist or are updated according to sitemap<br>Imported blocks are assembled in blueprint order | Blueprint and selected blocks conflict materially<br>Assembly requires redesign |
| 7 - Copywriting pass | Assembled pages<br>`SITE_BRIEF.md`<br>`WEBSITE_AUDIT.md` | Write page/section headlines, body copy, CTAs, microcopy, and SEO draft copy if applicable<br>Remove unsupported claims<br>Record unresolved copy questions | Redesigning layout<br>Changing visual hierarchy except to flag a blueprint issue<br>Adding unsupported promises | `COPY_DECK.md` | Copy deck mirrors implemented page/section structure<br>CTAs are clear | Required facts are unknown<br>Legal/commercial claims need client approval |
| 8 - Brand / visual adaptation pass | Assembled pages with copy<br>`VISUAL_ADAPTATION_NOTES.md` if existing<br>Brand inputs/assets | Apply approved colors, typography choices, spacing adjustments, imagery, logos, icons, and visual consistency fixes<br>Replace placeholders with approved assets<br>Log deviations from source blocks | Changing page strategy<br>Adding sections without approval<br>Changing copy positioning materially | `VISUAL_ADAPTATION_NOTES.md` | Visual adaptation notes record brand inputs, changes, deviations, and risks<br>Pages are visually coherent across desktop and mobile | Brand inputs are missing for a required decision<br>The selected block cannot support brand adaptation without redesign |
| 9 - Nuvio integration pass | Assembled/adapted pages<br>`SITEMAP.md`<br>`PAGE_BLUEPRINTS.md` | Integrate confirmed contact, WhatsApp, booking, newsletter, SEO basics, analytics/Umami, public runtime env, CMS mapping needs, and assets according to technical docs<br>Record status and notes<br>Create or update `INTEGRATION_CHECKLIST.md` | Guessing backend endpoints<br>Changing backend contracts<br>Inventing CMS architecture | `INTEGRATION_CHECKLIST.md` | Integration checklist records each applicable flow, status, notes, and validation needs<br>No unsupported contracts were invented | Endpoint or payload contract is unknown<br>Required env/secrets are missing |
| 10 - CMS/content mapping | Final-ish static pages<br>`PAGE_BLUEPRINTS.md`<br>`COPY_DECK.md` | Map content to existing CMS fields/blocks<br>Mark editable vs static content<br>Define fallbacks and ownership | Inventing CMS architecture<br>Adding schema/migrations<br>Changing backend model | `CMS_CONTENT_MAP.md` | Each relevant content item has CMS/static status, fallback, owner, and notes<br>Unmapped items are explicit | CMS field/block does not exist for a required editable item<br>Mapping would violate Nuvio SEO/settings data boundaries |
| 11 - QA pass | Built site or preview environment<br>Current artifacts<br>Validation commands/checks | Run scoped checks<br>Classify issues as P0/P1/P2/deferred<br>Record expected vs actual | Fixing issues before logging them unless the task specifically combines QA and fix<br>Reopening strategy/design<br>Deploying | `WEBSITE_QA_MATRIX.md` | QA matrix records checks, results, severity, status, owner, and notes<br>P0/P1/deferred items are clear | Required validation environment is unavailable<br>A P0 blocks safe continuation |
| 12 - Final polish | `WEBSITE_QA_MATRIX.md`<br>Approved fix list<br>Current site | Fix approved P0/P1<br>Apply cheap P2 polish that does not alter scope<br>Record final readiness and deferred items | Rewriting the site<br>Adding new sections/features<br>Changing strategy | `FINAL_REVIEW.md and DEFERRED_LIST.md` | Approved P0/P1 are fixed or explicitly blocked<br>Final review has readiness verdict | A P0 remains unresolved<br>A requested polish item is actually a redesign |
| 13 - Deploy / handoff | Final approved site<br>`FINAL_REVIEW.md`<br>Deployment environment | Deploy only if explicitly instructed<br>Record environment, URL, branch/commit, build command, deploy method, smoke result, rollback notes<br>Prepare handoff instructions | Deploying without approval<br>Committing secrets<br>Changing env names | `DEPLOYMENT_RECORD.md and CLIENT_HANDOFF.md` | Deployment record and client handoff exist<br>Smoke checks are recorded | Deployment approval is missing<br>Env/secrets are missing or unsafe |
