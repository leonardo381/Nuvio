# Visual Weight Rules

## Purpose

Use this guide during blueprint, assembly, and visual adaptation so pages feel intentional without becoming heavy.

## Visual Hierarchy Rules

- Every page needs one dominant hero message.
- Every section needs one job.
- Do not give every card the same visual weight.
- CTA elements should be easy to find but not repeated after every paragraph.
- Visual proof should support the message, not replace it.

## Density Rules

- Use dense content only when the visitor is comparing options or reviewing details.
- Keep hero and CTA sections spacious.
- Do not stack multiple dense card grids back to back.
- On mobile, reduce decorative density before reducing clarity.

## Section Rhythm

Recommended rhythm:

1. Clear promise.
2. Problem/context.
3. Solution or service structure.
4. Proof, preview, or process.
5. CTA/reassurance.

Avoid:

- hero -> huge grid -> huge grid -> FAQ -> huge CTA;
- repeating the same card pattern for every section;
- making every section dark, loud, or gradient-heavy.

## When To Use Mockups

Use mockups when:

- the product/backoffice/process is hard to understand without visuals;
- the page needs proof that the offer is real;
- screenshots are not available but a simple UI card can communicate the concept.

Do not use mockups when:

- they are unrelated decoration;
- they make mobile unreadable;
- they imply features that do not exist.

## When To Use Cards

Use cards for:

- service categories;
- short benefits;
- problem clusters;
- integration/module summaries;
- risk reducers.

Avoid cards for:

- long prose;
- every paragraph;
- content that should be a clear linear story.

## When To Use Steps

Use steps for process, onboarding, project phases, or "how it works". Keep labels short and action-oriented.

## When To Use Checklists

Use checklists for included capabilities, readiness items, practical outcomes, or risk reducers. Avoid using checklists as a substitute for clear explanation.

## When To Use Proof, Testimonials, Or Logos

Use proof only when real or approved. Do not invent client logos, testimonials, metrics, or outcomes.

If proof is missing, use:

- product preview;
- process clarity;
- practical risk reducers;
- direct CTA.

## When To Avoid Heavy Visuals

Avoid heavy visuals when:

- the page already has multiple grids;
- copy is still uncertain;
- mobile sections become long and repetitive;
- visuals imply unavailable functionality;
- performance would suffer from unnecessary images.

## Mobile-First Constraints

- Primary CTA must appear early and remain tappable.
- Text blocks should not exceed practical mobile reading length.
- Cards should stack cleanly.
- Mockups must remain readable or be simplified.
- Avoid side-by-side layouts that become confusing when stacked.

## CTA Rhythm

- Use one primary CTA label consistently.
- Use secondary CTA only when it helps navigation.
- Repeat CTA after major decision points, not after every section.
- Final CTA should be direct and specific.

## Common Visual Mistakes

- Overweight hero with no clear next step.
- Too many equal cards.
- Decorative mockups with fake data that look like real claims.
- Desktop-only spacing decisions.
- Changing the block's design during raw import instead of waiting for Stage 8.
